## **Reto**:  Head-dump - Web
## **Descripción**
Welcome to the challenge! In this challenge, you will explore a web application and find an endpoint that exposes a file containing a hidden flag.The application is a simple blog website where you can read articles about various topics, including an article about API Documentation. Your goal is to explore the application and find the endpoint that generates files holding the server’s memory, where a secret flag is hidden.The website is running [picoCTF News](http://verbal-sleep.picoctf.net:54334/).

## **Solución**
1. Al explorar el blog "picoCTF News", analicé las publicaciones del autor "John Doe". Identifiqué pistas críticas en los hashtags: `#swagger_UI` y `#API Documentation`. Esto me indicó que el objetivo no estaba en el contenido del blog, sino en la **interfaz de desarrollo** del servidor.
2. Utilicé técnicas de enumeración de directorios para adivinar la ruta de la API. Al añadir `/api-docs/swagger-ui.html` a la URL principal, logré acceder a la consola de **Swagger UI**, que estaba configurada incorrectamente y permitía ver todos los endpoints internos.
3. Dentro de Swagger, busqué en la sección de _Diagnostics_ y encontré el endpoint crítico: **`GET /heapdump`**.
4. Debido a que el archivo de memoria era muy pesado, el navegador se bloqueaba al intentar procesarlo. Utilicé la potencia de la terminal de Kali para una descarga directa y estable:

- **Comando:** `wget http://verbal-sleep.picoctf.net:49499/heapdump
1. Para no buscar manualmente entre gigabytes de datos binarios, utilicé terminal para filtrar la información:

- **Comando:** `strings heapdump_file | grep "picoCTF"`

```

```
## **Notas adicionales
- **Concepto clave:** Un _heap dump_ es una fotografía instantánea de la memoria RAM del servidor. Como la bandera es una variable activa en el código, sabía que debía estar escrita en algún lugar de ese archivo binario.
